## 一、已确认的完整机制

### 1. 触发条件
`POST /bff/passport/verifyCode/sms/send` 命中风控时返回：
```json
{
  "success": false,
  "code": 420,
  "data": {
    "securityContext": {
      "punishId": "2110651922719318017",
      "verifyType": 1,
      "verifySdk": 1
    }
  }
}
```

### 2. 滑块验证码技术栈
- 厂商：数美科技（SHUMEI），`organization: qvdTr7A9k1DIU04ha4eP`
- WebView 页面：`https://castatic.fengkongcloud.com/pr/v1.0.4/index.html`
- 核心接口：
  - `GET https://captcha1.fengkongcloud.cn/ca/v1/register?...&captchaUuid=xxx` → 返回 `bg`(背景图)/`fg`(拼图块图)/`rid`(本次验证会话id)
  - `GET https://captcha1.fengkongcloud.cn/ca/v2/fverify?...&rid=xxx` → 返回 `riskLevel: PASS` 或 `REJECT`
- 类型：**拼图填充式**滑块（3个候选缺口位置，需把左侧拼图块拖到正确缺口）

### 3. 验证通过后的凭证组装（已验证正确）
验证通过后，App 在**第二次**请求 `verifyCode/sms/send` 时多带一个 header：
```
x-mcd-sec-verify: base64("{punishId};{verifyType};{当前毫秒时间戳};{通过验证的rid}")
```
示例（已用真机抓包验证）：
- 明文：`2110651922719318017;1;1792053623002;202610151640151e7827e4404035e31d`
- Base64：`MjExMDY1MTkyMjcxOTMxODAxNzsxOzE3OTIwNTM2MjMwMDI7MjAyNjEwMTUxNjQwMTUxZTc4MjdlNDQwNDAzNWUzMWQ=`

带上这个 header 后，第二次请求返回 `success: true, code: 200`，验证码真正发出。

**关键结论**：这个拼接是纯本地逻辑，不需要额外请求麦当劳服务端换取 token，只要拿到一个 `riskLevel: PASS` 的 `rid` 即可。

## 二、浏览器复现情况

### 已验证可行
- 直接打开 `https://castatic.fengkongcloud.com/pr/v1.0.4/index.html`
- 用 JS 调用 `window.deliverNativeParams(JSON.stringify({organization: 'qvdTr7A9k1DIU04ha4eP', appId:'default', channel:'DEFAULT', data:{os:'android', sdkver:'1.5.1'}, https:true}))` 可以成功加载出验证码（绕过了 `shumei://requestnativeparams` 这个只有真实 App 才能响应的 scheme）

### 当前卡点
- 用 JS `dispatchEvent(new TouchEvent(...))` 模拟拖拽，`event.isTrusted` 始终为 `false`
- 即使位置算得完全精确，`fverify` 依然返回 `riskLevel: REJECT`
- 结论：**该版本滑块有行为/事件可信度检测**，纯 JS 模拟事件无法绕过，需要 CDP 协议层的真实鼠标事件（`Input.dispatchMouseEvent`），这个在当前工具链里还没打通（Drag 工具需要 a11y 树里的 uid，但滑块是纯 div/css，没有语义节点）

### 7.2 关键发现1：707053 vs 420 由出口 IP 质量决定（新增，重要）

- 走代理池的**数据中心代理**（`61.155.141.105`，账号绑定 `mcd_proxy_003`）→ `code 707053 "该账号存在安全风险，暂时无法注册"`，**硬拦，根本不出滑块**（两个号 `16752934813`/`17717295039` 都是）

- 推论：触发并走通滑块验证**必须用干净/住宅 IP**；数据中心代理会被风控直接黑名单成 707053。这解释了之前为何一直拿不到 420。

### 7.3 关键发现2：解答第 6.3 节遗留疑问——跨设备可配对

之前担心"浏览器拿的 PASS rid 没有配对 punishId"。实测证明**不需要同设备**：
- `punishId` 来自 mcd 的 420（python 端，直连 IP，无数美设备指纹）
- `rid` 来自浏览器端人工滑动的数美 PASS（浏览器的数美设备指纹，与 python 端完全不同）
- 二者拼接重发**直接 success**。说明 mcd 服务端只校验：punishId 有效 + rid 是该 organization 下一个真实的近期 PASS + 时间接近，**不交叉校验"滑块设备 == 请求设备"**。

### 7.4 关键发现3：x-mcd-sec-verify 中间字段是 verifySdk（修正旧公式）

jadx 脱壳 `oe.x`（`CaptchaDialog.kt`）`onSuccessWithContent` 确认：
```
base64_nowrap(f"{punishId};{verifySdk};{System.currentTimeMillis()};{rid}")
```
中间是 **`getVerifySdk()` 不是 `getVerifyType()`**；本次 verifyType/verifySdk 都=1，看不出差别，但一旦不等按旧公式会错。`verifyType` 只决定验证码形态（1/其他=滑动，2文字点选，3图标点选，4语序点选，5空间推理）。Base64 用 `NO_WRAP`（flag 2）。

## 十、d 值汇总 + 风控升级教训（2026-10-16）

### 10.1 d 是什么 / 怎么生成
- 数美(SHUMEI)设备指纹，mcd 请求头 `d`。两种形态：`B`+smid（已注册，deviceprofile/v4 返回）；`D`+base64(vdata)（注册前采集负载 `{organization,os,appId,data,tn,ep}`）。
- 生成链：`qf.a`(BFFHeaderInterceptor) 每请求 `d=SmSDK.getSmDeviceId()`→`SmAntiFraud.getDeviceId()`→"B"+smid/"D"+vdata；init 在 `SmSDK.initShumei`(org=qvdTr7A9k1DIU04ha4eP,RSA公钥…)。smid/vdata 来自 native `deviceprofile/v4`+libsmcp(.so)，纯 Java/Python 复刻不出。
- **重启 APP → 重跑 deviceprofile → 新 deviceId/新 d，token 不变**。自造 d 需逆 libsmcp 或 frida hook `SmAntiFraud.getDeviceId`。

### 10.2 d 与风控（实测）
- 不带 d → **707053**（账号安全风险/硬拦，不出滑块）；带合法真实 d → **420**（正常滑块，可过）。
- 铁证：同号 13520093034，无 d→707053，带抓包真实 d→420。**d 是 707053 的决定性开关**。

### 10.3 我们怎么用（自用单机单号）
抓包拿真机 `token+d` → `set_device.py` 写进账号凭证 → `build_headers` 带上（ContextVar「存在就带」，requests 不变）。单账号全链路验证通过（d→420→自动滑→重发→短信）。

### 10.4 ⚠️ 引发的风控升级：706070（核心教训）
测试中**反复用同一个借来的 d 跨多个号 + 高频发码** → 风控从 707053 升级成 **`706070 当前账号设备环境异常`**，连真机 APP（重启/卸载重装/直接登录）都被拦。
- 根因：风控抓「**一个设备指纹 ↔ 多账号 + 高频**」（典型滥用特征）。
- 706070 挂在服务端账号/设备上，**重装/重启清不掉**（deviceId 源于硬件 + 账号被标记），**代码层解决不了**，只能**停手冷却（数小时~数天衰减）+ 换真正独立新号/环境**。
- **铁律：一个 d 只配一个号、按人频率用**；多账号共用一个 d → 必被 706070。规模化多 d 轮换 = 不做。

### 10.5 已知风控码阶梯
| 码 | 含义 | 触发 | 解法 |
|---|---|---|---|
| 420 | 出滑块挑战 | 正常风控 | 过滑块 |
| 707053 | 账号存在安全风险 | 脏 IP / 无 d / 账号风险 | 干净 IP + 合法 d + 好号 |
| **706070** | **设备环境异常** | **一个 d 多账号 / 高频（升级）** | **停手冷却 + 独立新环境** |
| 801005 | 发码次数超限 | 单号发太频繁 | 降频 |
