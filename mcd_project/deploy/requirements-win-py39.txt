# ============================================================================
# mcd_project / captcha_login_worker.py 的 Windows 依赖锁定清单
#
# 范围：**只覆盖 captcha_login_worker.py 的实际导入闭包**，不含 mcd_server /
#       scheduler / demo.py / deploy 工具链的依赖（flask、schedule、paramiko 等一律不装）。
#
# 闭包怎么算的：从 captcha_login_worker.py 起，只跟**模块级 import** 递归
#   → 本地模块：config / login_manager / mcd_api / mcd_shumei_d / proxy_pool /
#     proxy_failure_handler / account_proxy_binding / ip_location / utils / exceptions
#   → 第三方顶层只有 6 个：redis、requests、Pillow、DrissionPage、ddddocr、pycryptodome
#     （frida 不在链上：device_builder 是 device_pool_redis 里函数内的惰性导入）
#   → 再用 importlib.metadata 按 sys_platform=win32 / py3.9 求值 marker 展开传递依赖
#
# 基准：Mac 本机 /Users/houjie/venv/python3-forcrawl（Python 3.9.17）的真实安装版本
# 目标平台：Windows x64 + CPython 3.9（用 python.org 最后一个 Windows 安装版 3.9.13，
#           cp39 ABI 与 3.9.17 完全一致，所有 cp39 wheel 通用）
#
# 36 个包全部有 win_amd64/cp39 预编译 wheel —— Windows 上不需要 MSVC、不需要编译源码。
#
# 与 Mac 环境的偏差只有 2 处：
#   pycryptodome 3.9.8 → 3.9.9   3.9.8 最高只有 cp38 的 win wheel（Mac 上是源码编译的）
#   pyreadline3  3.5.4           Mac 上不存在（humanfriendly 的 Windows-only 依赖）
# 其余 34 个与 Mac 逐版本一致。
#
# 未安装：gunicorn（Windows 不支持）、frida（PyPI 只发 .egg，pip 装不了，且不在运行链上）
#
# 用法：pip install -r requirements-win-py39.txt
# ============================================================================
