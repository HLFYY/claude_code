# Android 7.0.45.1 接口核验（进行中）

## 2026-11-23 已确认的事实

- ADB 连接设备的 `com.mcdonalds.gma.cn`：`versionName=7.0.45.1`，`versionCode=1248`。
- 2026-11-13 历史抓包中的 24 条 v4 请求，使用本次提供的 v4 AK/SK 均可重算出完全相同的 Authorization 和请求体 HMAC；旧 SK 对这 24 条请求均不匹配。
- 重算 Authorization 前必须排序查询参数。直接使用 URL 中原始参数顺序，会误报其中两条签名不匹配。
- 当前两个已知配置的 AES key 相同，v4 AK/SK 不同。因此不能只修改 `v` 而保持旧签名密钥。
- `signKey` 尚未证明参与项目当前使用的 v4 Authorization 或 body HMAC，不能用它替代 v4 SK。
- 不能由两个样本推导“每个版本都更换所有密钥”，也不能证明版本号是唯一选择条件。当前新配置对应观测到的 `p=102, ct=102`；同版本不同渠道/构建须重新取证。
- 签名匹配仅说明签名实现与样本一致，不证明登录、风控、下单或支付成功。历史发码样本业务失败，不能归为接口成功。

## 版本配置的使用

`mcd_profiles.py` 集中保存两个已知客户端配置；`mcd_api.py` 统一读取 AES、v4 AK/SK、`v`、`p`、`ct` 和 User-Agent。

经用户确认实施适配，当前默认 `7.0.45.1`。也可在进程启动前显式设置：

```sh
export MCD_APP_VERSION=7.0.45.1
```

配置在模块导入时加载，修改环境变量后需重启服务及 worker；不要在同一进程运行时修改模块全局变量切换版本。未配置的版本直接报错，不回退到旧密钥。

新版业务基址为api2.mcd.cn。回滚时设置 `MCD_APP_VERSION=7.0.41.0`，恢复旧版本/密钥和原业务基址api.mcd.cn；原本明确走API2_BASE的登录等接口仍保持api2。下文各阶段的“暂不修改”是当时的取证记录，当前实施范围以用户最终确认及拟修改清单的更新为准。

SMS worker 复用 `mcd_api` 的 AES 和 build_headers，随进程配置同步切换。可选 v5 提单分支的版本头同步读取配置，但 v5 签名及其余头部未通过真机核验，不能据此宣布兼容。

这次没有修改业务请求参数、接口路径、风控字段或凭证保存逻辑，也没有将本次提供的 signKey 加入未确认的算法。
