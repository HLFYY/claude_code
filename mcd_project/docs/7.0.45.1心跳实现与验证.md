握手签名：

```text
message = ct + meddyId + scene + sid + st + sv + v
sign = Base64_NO_WRAP(HMAC_SHA256(UTF8(wskey), UTF8(message)))
```

无分隔符；本场景 scene=""、sv="v4"。wskey 直接 UTF-8 编码，不先 Base64 解码。
sid 为空、当前版本未配置 wskey、时间偏移或代理配置无效时跳过连接并记录原因，
不回退到其他密钥，也不把无效代理悄悄改成直连。

## 2. 未改动的行为与调用方

- 公共函数 run_keepalive、keepalive_account、launch_account、read_last_result 的参数保持不变。
- mcd_server 的 POST /api/maintenance/keepalive 与 keepalive_worker 的任务格式不变。
- GET /api/maintenance/keepalive/last 仍读取原有批处理结果。
- POST /api/maintenance/launch 只调用 launch_account，本来就不启动 pulse，这次不增加。
- 账号标识长度/acc_ 校验、登录要求、刷新凭证、Redis 写入及 dead 平台回写逻辑不改。
- 仍按“假启动 -> 会话校验 -> 条件满足后启动心跳”执行；默认 180 秒 daemon 异步会话。
- 心跳失败不把会话校验的 alive 改成 dead，不删除凭证；后台断线不自动重连。

上述三分钟和不重连规则限定于 keepalive。pulse_guard 是独立的常驻对照实验：
仍须显式 --phones，按连接取代理、重连前重读凭据，断线按原有5秒起步、最高300秒的
退避重连；没有把它改成三分钟会话，也没有把其常驻重连策略带入 keepalive。
guard 直接导入纯协议模块，不通过 keepalive 间接加载 mcd_api；本次不新增 Redis 写入。
日志文件初始化移到 main 参数校验后，导入/离线测试不会创建服务器上的日志文件。

接口/队列返回表示批处理已完成，不表示后台三分钟心跳已经结束。
alive 仍是会话校验结论，不是 WS 成功、sid 续期或设备风控解除。
本次不引入账号级连接去重；重复任务仍可能产生多个临时心跳线程。

## 3. 时间、代理及日志

Java 使用 MCDTimeTable 的服务端校正时间；偏移初始为 0，之后可从 HTTP 响应 Date 校正。
Python 当前没有共享自动校时机制，本次不修改 mcd_api 或额外请求校时端点：

- st 默认取本机毫秒时间；请保证运行机器时间同步。
- 可选环境变量 MCD_PULSE_TIME_OFFSET_MS 为整数毫秒，含义是服务端时间减本机时间；默认 0。
- 偏移影响两个入口的 WS 握手时间戳，不影响 HTTP 签名或 monotonic 调度。
- 不要复制旧抓包的 st/sign 或固定一次观察所得的偏移；非整数配置会停止本次连接。

复用已有 HTTP CONNECT 代理，支持 host:port、http URL、用户名密码和 IPv6 地址；
不新增 SOCKS/HTTPS 代理能力。网络环境及短效代理能否覆盖 180 秒仍需部署后验证。

结束日志格式：

```text
保活pulse结束 <账号标识> reason=deadline sent=11 ack=11 other=1 invalid=0
```

上述数值仅为格式示例，不是本次实连结果。reason 可为 deadline、peer_closed 或异常类名。
只记录计数和异常类型，不输出密钥、sid、握手头、消息正文或原始异常内容。
ACK 计数不是逐请求关联确认；当前只统计消息类型，未增加 ACK 超时判死策略。

2. 使用实际运行保活进程的 Python 环境安装依赖，确认 websocket-client==1.9.0。
3. 队列路径重启 mcd-keepalive-worker.service；HTTP 路径重启 mcd_server 的 Gunicorn workers。
   若已有运行中的 mcd-pulse-guard.service，需单独重启以载入修复；不要未经授权新开启常驻实验。
4. 若配置时间偏移，需在对应进程环境中设置并重启；默认不设置。
5. 部署后用受控账号验收握手及结束计数，检查代理、关闭原因和 ACK；不要据此宣称续期成功。
